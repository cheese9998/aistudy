## 二、3 个高性价比简历项目（强烈推荐）

### 项目 1：企业知识库 RAG 问答系统（最稳的"保底项目"）

**业务背景**：公司内部有 1000+ 份产品手册 / API 文档 / 会议纪要，员工检索效率低。

**技术栈**：
- 前端：Vue 3 + Element Plus + 流式输出
- 后端：FastAPI + WebSocket/SSE
- RAG：LangChain + BGE Embedding + BGE Reranker
- 向量库：Milvus / pgvector
- LLM：DeepSeek-V3 / Qwen2.5
- 部署：Docker + Nginx

**核心难点**（写 3-4 个，体现深度）：
1. **复杂 PDF 解析**：含表格、公式、图文混排 → 用 LlamaParse + Unstructured
2. **检索准确率低**：通用检索召回 60% → 加 BGE Reranker + 混合检索（BM25 + 向量）→ 提升到 88%
3. **长文档超出上下文**：30+ 页文档 → 父子切片 + 上下文压缩 + Map-Reduce
4. **幻觉问题**：答案有编造 → 强制要求引用原文 + 拒答机制（低于阈值返回"未找到相关信息"）

**量化成果**：
- 文档检索准确率：78% → 92%
- 平均响应时间：< 2.5s
- 节省工程师查阅时间：15 人时/周
- 覆盖 30+ 部门、日均 2000+ 次查询

---

### 项目 2：多 Agent 协作办公平台（高级岗必写）

**业务背景**：销售团队每周花 8 小时写周报、查客户资料、汇总邮件

**技术栈**：
- 编排：LangGraph（图状态机）
- Agent：研究 Agent（搜索/数据库）+ 写周报 Agent + 审稿 Agent
- 工具：飞书 API、企查查、邮件 MCP
- 记忆：PostgreSQL + Redis
- 前端：React + 流式输出 + Markdown 渲染
- 部署：K8s + Helm

**核心功能**（写清楚流程）：
1. 用户说"帮我写这周周报"
2. 研究 Agent 读取飞书任务、销售数据、邮件
3. 写周报 Agent 生成初稿
4. 审稿 Agent 检查格式、可读性、数据准确性
5. 人工确认后发送给老板

**核心难点**：
1. **多 Agent 协作循环**：用 LangGraph 状态机 + Checkpointer 持久化
2. **工具调用错误恢复**：用 MCP 协议 + 失败重试 + 人工兜底
3. **上下文管理**：长对话超出窗口 → 摘要压缩 + 关键信息提取
4. **成本控制**：每月 LLM 成本预算 5000 元 → 缓存 + 小模型预处理 + Token 限流

**量化成果**：
- 销售周报时间：8h → 30min（**94% 节省**）
- 200+ 销售使用
- 月节省人力 200+ 工时

### 项目 3：Dify 二次开发 - 企业智能工单助手

**业务背景**：客服每天处理 500+ 工单，重复问题占 60%

**技术栈**：
- 平台：Dify（私有化部署）
- 工作流：多轮对话 + 知识库检索 + 工单创建工具
- 知识库：5000+ 份历史工单 + 产品 FAQ
- 对接：企业微信 / 飞书 / 自研工单系统
- 自定义插件：Dify Plugin SDK（工单状态查询、自动分类）

**核心功能**：
1. 员工通过企业微信机器人提问
2. Dify 意图识别 + 知识库检索
3. 找到答案 → 直接回复
4. 找不到 → 自动创建工单
5. 紧急工单自动通知值班人员

**核心难点**：
1. **意图识别准确率低**：用 LLM 分类 + 规则兜底
2. **历史工单噪声大**：用 LLM 预处理（去除个人信息、提取关键问题）
3. **与企业系统对接**：基于 Dify Plugin SDK 开发自定义工具

**量化成果**：
- 工单自动解决率：35%
- 客服日均处理量：500 → 250
- 客户首次响应时间 ↓50%

## 三、简历项目包装技巧

### 1. STAR 法则
每个项目/工作经历，用 4 段写：
- **S**ituation：业务背景（最好贴目标公司行业）
- **T**ask：你的角色 + 负责模块
- **A**ction：技术选型 + 难点解决（写具体技术名）
- **R**esult：可量化指标（用百分比 / 数字）

### 2. 技术关键词密度
HR 和简历筛选系统（ATS）会扫描关键词。务必包含：
```
LangChain, LangGraph, RAG, Agent, Prompt Engineering,
FastAPI, Docker, Python, LLM, Vector Database, Milvus,
Dify, OpenAI API, Claude, HuggingFace
```

### 3. 数字量化（非常重要）
- ❌ "提升了系统性能"
- ✅ "响应时间从 5s 优化到 1.5s，提升 70%"
- ❌ "做了 RAG 系统"
- ✅ "基于 LangChain + BGE Reranker 构建企业 RAG，准确率 78% → 92%"

### 4. GitHub 包装
- README 写好、有效果截图、有 Demo 链接
- 每个项目独立 repo
- 提交记录稳定（不要最后一天狂 commit）
- 100+ stars 简历直接加分

## 四、简历投递策略

### 1. 渠道优先级
1. **内推**（成功率最高） - 脉脉、LinkedIn、校友群
2. **BOSS直聘** - 直接和 HR 聊，反馈快
3. **猎聘** - 适合中高端岗位
4. **拉勾** - 互联网岗位多
5. **公司官网** - 大厂校招通道

### 2. 投递节奏
- **海投期**：每天 30-50 份，2 周
- **精准期**：根据反馈调整简历，每天 10-20 份
- **面试期**：减少投递，集中准备

### 3. 简历版本
针对不同方向准备 3 个版本：
- **AI 应用后端**版本（强调 Python / FastAPI / Docker）
- **RAG 工程师**版本（强调 LangChain / 向量库 / 文档处理）
- **Agent 工程师**版本（强调 LangGraph / 多智能体 / MCP）

### 2. 项目深挖准备
每个项目准备 5-8 个"细节追问"：
- 为什么选 LangChain 不选 LlamaIndex？
- 切片大小怎么定的？做过实验吗？
- Reranker 为什么能提升？原理是什么？
- 向量库为什么选 Milvus？HNSW 了解吗？
- 怎么评估 RAG 效果？用了什么指标？
- 遇到过什么坑？怎么解决的？
- 成本怎么算的？一个月多少钱？
- 如果让你重做一遍，会改什么？

### 3. 高频算法题
- 二分查找、链表、二叉树、动态规划（基础）
- LRU、LFU 缓存
- 字符串处理（最长公共子序列）
- SQL 必备

### 4. 行为面试
- 最有成就感的事？
- 最大的技术挑战？怎么克服的？
- 为什么选择我们公司？
- 未来 3-5 年规划？

## 六、薪资谈判

### 1. 跳槽涨薪规律
- 平跳：30%+ 
- 升一级：50%+
- 大厂跳中小厂：可谈到 double

### 2. 谈薪技巧
- 先让对方出价
- 不要主动说期望薪资
- 强调自己带来的价值（量化）
- 谈总包：base + 股票 + 签字费 + 年终
- 留 1-2 个 offer 作为筹码
